# Figma Foundations Schema 0.1.0

Version: 0.1.0. Date: 2026-10-21. Distribution: developer preview.

This document and the versioned schemas define the implemented FFS contract. Architectural rationale is documented in [design decisions](../docs/design-decisions.md). FFS is independently developed and is not an official Figma standard. It does not require DTCG compatibility.

The words MUST, MUST NOT, SHOULD, and MAY express requirements for implementations of this version.

## 1. Scope and baseline

FFS serializes reusable Figma Design foundations, their authoring relationships, and the resources needed to interpret them. Its scope includes variables, collections and extended collections, native styles, property presets, themes, assets, provenance, and exact library dependencies.

The field baseline is `@figma/plugin-typings` **1.142.0**, supplemented by the documented REST distinctions described below. [The baseline inventory](../docs/figma-baseline.json) records the reviewed date, input SHA-256, native data fields, and required fields. [The field reference](../docs/fields.md) enumerates the resulting FFS contracts, including nested records, enums, and union alternatives.

This baseline fixes the meaning of the data contract. New Figma features require an explicit format update; they do not silently become valid. Product plan limits do not change the format. FFS is not constrained to an individual plugin's current permissions.

Application screens, component trees, variant systems, instance overrides, prototype navigation, per-node timelines, editor selections, consumers, and API methods are outside Foundations. Reusable motion styles and bounded vector/pattern artwork are included. A separate component/document format can consume foundation IDs.

## 2. Files and validation layers

The schema files use JSON Schema Draft 2020-12:

| File | Meaning |
| --- | --- |
| `schemas/0.1.0/package.schema.json` | Authored package, resources, and expression grammar |
| `schemas/0.1.0/values.schema.json` | Concrete resolved value contracts under `$defs/type-*` |
| `schemas/0.1.0/manifest.schema.json` | Authoring manifest with resource-file paths |
| `schemas/0.1.0/resources.schema.json` | Resource dictionary used by a manifest fragment |

Package-schema validation is structural. It deliberately cannot prove that a reference resolves to a valid paint, for example. Complete validation MUST also resolve relationships and validate concrete values against `values.schema.json`. Passing only the package schema is not full FFS conformance.

JSON MUST contain no duplicate object keys or nonfinite numbers. Strings resembling references are ordinary data unless placed in an explicit expression. Objects MUST use only the declared core keys; custom metadata belongs in namespaced `extensions`.

All package, resource, group, mode, and dependency IDs use ASCII letters, digits, `.`, `_`, and `-`, beginning with a letter or digit. They are case-sensitive. IDs are immutable identities, not paths. Display names may duplicate each other and may contain arbitrary Unicode. Changing a name or organization MUST NOT change a reference's meaning.

## 3. Package structure

An authored package has these required fields:

```json
{
  "format": "figma-foundations",
  "formatVersion": "0.1.0",
  "package": {
    "id": "example-foundations",
    "name": "Example Foundations",
    "version": "1.0.0"
  },
  "dependencies": {},
  "resources": {},
  "organization": [],
  "sources": {}
}
```

`formatVersion` versions this contract. `package.version` versions authored content independently; it is an exact semantic version without build metadata. A distributable package MUST identify immutable content. Authoring autosave revisions and release workflows remain tool concerns.

`resources` maps resource IDs to definitions. A resource MUST NOT redundantly declare its own ID.

`organization` is an ordered tree. A resource entry is `{ "resource": "id" }`. A group is `{ "id": "group-id", "name": "Colors", "children": [] }`. Group IDs are unique within a package. Resources may appear in several groups or none. Groups do not supply inherited types, values, modes, or naming prefixes.

`sources` maps source IDs to source-document records. A source declares `product: "figma-design"` and `apiSurface: "plugin" | "rest" | "manual"`. It may include `fileKey`, `versionId`, `capturedAt`, `apiVersion`, and `colorProfile`. Native version-history IDs are recorded when known and are never invented. `apiVersion` is the captured API version, not the schema version or typings package version.

An optional `$schema` string is a tooling hint. It does not override `formatVersion`.

## 4. Resource definitions

Each resource requires `kind` and `name`.

| Kind | Required fields beyond name/kind | Meaning |
| --- | --- | --- |
| `value` | `dataType`, `expression` | Reusable typed value |
| `variable` | `dataType`, `collection`, `values` | Native variable with values per mode |
| `collection` | `modes`, `defaultMode` | Native collection or extended collection |
| `style` | `family`, `expression` | Native reusable style |
| `preset` | `target`, `expression` | Reusable property assignment set |
| `theme` | `selections` | Collection-mode selections |
| `asset` | `mediaType`, `content` | Bundled or external content |

Common optional fields are `description`, `descriptionMarkdown`, `documentationLinks`, `tags`, `deprecated`, `hiddenFromPublishing`, `sourceLinks`, and `extensions`. A deprecation record has a reason and may address a replacement resource. A replacement is advisory and MUST NOT silently redirect references.

`sourceLinks` records one or more Figma correspondences: `source`, `objectId`, optional `libraryKey`, `remote`, `publishStatus`, and `fields`. `publishStatus` uses `UNPUBLISHED`, `CURRENT`, or `CHANGED`. `fields` maps stable local item/field identifiers to captured source locations. Native IDs and library keys MUST NOT substitute for FFS resource identity.

Custom metadata is keyed by reverse-domain namespaces, for example `"example.org/editor"`. Consumers preserve metadata they do not understand. Required semantic extensions are declared in package `requires` as exact `{ "id", "version" }` descriptors. A core-only evaluator MUST fail with `EXTENSION_REQUIRED` when such an extension is required. This prevents treating unknown semantics as harmless metadata.

### Values, variables, styles, and presets

The 27 value types are listed in the generated field reference. They include scalar values, quantities, colors, geometry, paints, effects, grids, typography, strokes, corners, layout, motion, and vector artwork.

Native variable types are `boolean`, `color`, `number`, `string`, `easing`, and `timing`. A variable's `collection` is a typed collection address. `values` maps every owning collection mode ID to one expression. Root variables MUST provide exactly those mode IDs: no implicit fallback and no extra modes. Optional `scopes` and `codeSyntax` preserve applicability and platform syntax. `ALL_SCOPES` is exclusive; `ALL_FILLS` cannot be combined with individual fill scopes. Scopes MUST match the declared native variable type.

Style families map to resolved types as follows:

| Family | Resolved type |
| --- | --- |
| `paint` | `paintStack` |
| `text` | `textStyle` |
| `effect` | `effectStack` |
| `grid` | `gridStack` |
| `motion` | `motionStyle` |

Preset targets map to `textProperties`, `stroke`, `corners`, `layoutProperties`, and `motionProperties` through `text.properties`, `stroke.properties`, `corner.properties`, `layout.properties`, and `motion.properties` respectively.

A Text Style uses only the native Text Style field surface. Additional text-node/range settings use `text.properties`; a preset MUST NOT be represented as a fictitious native style. A preset describes properties without constructing a component or assigning them to a particular node.

## 5. Addresses and dependencies

A typed address is `{ "resource": "id" }`, optionally with `"dependency": "alias"`. Without `dependency`, it refers to the package in which that address was authored. Dependency aliases are resolved in that author's namespace, not the eventual consumer's namespace.

Each dependency descriptor contains `id`, exact `version`, package-relative `path`, and lowercase hexadecimal `sha256`. The digest covers the exact UTF-8 bytes of the assembled dependency package file, including whitespace. It is not a hash of JSON after reserialization. The loader MUST verify the digest and package identity before using the dependency.

Dependencies are assembled packages, not authoring manifests. This prevents a manifest's unchanged digest from concealing changes to separate resource fragments. Dependency cycles and different content under the same package ID/version are invalid. Network resolution and floating versions are outside this version; the reference loader works offline.

All file paths MUST be nonempty, package-relative forward-slash paths without empty segments, `.`, or `..`. Absolute paths, backslashes, and symlinks escaping the package directory are invalid. A package and its relative files travel together.

## 6. Expressions

An expression contains exactly one of these keys:

| Key | Payload and behavior |
| --- | --- |
| `literal` | A complete concrete JSON value; nested expression-like data is not evaluated |
| `ref` | Address of a value-bearing resource; optional `pointer` and local `modes` |
| `record` | Dictionary of child expressions, constructing a concrete object |
| `list` | Ordered array of child expressions |
| `bind` | `{ "variable": "id", "dependency"?: "alias" }`, preserving a native property binding |
| `color` | Domain-specific composition of a color and an alpha value |

`ref` may read a value, variable, style, or preset. It retains the authored relationship but does not create a native property binding. An alias between native variables is represented with a direct reference and MUST retain the same declared native variable type, even when different types share a JSON representation, such as number and timing. A reusable value has no native variable identity to bind to.

`bind` requires a variable and an eligible destination field. It is invalid inside variable mode values. It MUST NOT pin a mode independently of the consuming context. A variable's concrete value is validated against the actual destination field, preserving required units and shapes.

Examples:

```json
{ "literal": { "amount": 16, "unit": "px" } }
```

```json
{ "ref": { "resource": "surface-color" } }
```

```json
{ "record": {
  "itemId": { "literal": "base" },
  "type": { "literal": "SOLID" },
  "color": { "bind": { "variable": "surface-color" } }
} }
```

### Pointer selection and local contexts

`pointer` is RFC 6901 JSON Pointer applied to the target's resolved value. The empty pointer selects the complete value. Escapes are `~0` for `~` and `~1` for `/`. Array indexes MUST be canonical nonnegative decimal integers; leading-zero indexes and the append token `-` are invalid for reads. Missing targets are errors.

Reference-local `modes` is an array of collection selections evaluated in the referencing author's namespace. Its effects apply only inside that reference's evaluation subtree. Siblings retain their prior context. Pointer selection is applied before deciding which bindings are preserved. If a local override would make a preserved native binding observe a different mode than the actual consuming context, validation MUST fail with `BINDING_CONTEXT` rather than materialize a misleading binding. Bindings outside the pointer-selected subtree do not cause this error.

### Color composition

The color expression has `base` and `alpha` child expressions, `alphaUnit: "ratio" | "percent"`, and `operation: "replace" | "multiply"`.

`base` resolves to a color and `alpha` to a finite number. The permitted alpha range is [0,1] for ratio and [0,100] for percent. Normalize percentage by dividing by 100. Replace sets that alpha; multiply multiplies the base color's alpha by it. The base color space and channels are preserved. Native bindings are not allowed inside this operation; variable relationships use `ref` expressions.

This supports an authored composed color while retaining both aliases and the explicit opacity unit. It does not guess whether a captured native operation replaces or multiplies alpha. An importer must map the source operation correctly. No unrestricted arithmetic, scripting, implicit deep merge, or wildcard evaluation is included.

## 7. Collections and themes

`modes` maps immutable local mode IDs to `{ "name": "…" }`. `defaultMode` MUST address a declared mode. Optional `modeOrder` lists the complete mode set exactly once. Optional `variableOrder` lists the complete owned/inherited variable set exactly once. Omission means order is unspecified; it MUST NOT be inferred from mutable labels. Figma's API order is captured where available; it is not claimed to expose every authoring-UI ordering detail.

A selection is `{ "collection": <address>, "mode": "mode-id" }`. A theme contains an ordered `selections` array. One selection list MUST NOT select two views of the same root collection, including a parent and its extension. Different collections may have identically named modes without any coupling.

Evaluation starts with root defaults, applies requested themes left to right, then caller mode selections. Later theme selections replace earlier selections for the same root collection; values are not deep-merged. Each variable uses the selected view of its own collection. References across collections use the target collection's context, not the caller's mode label.

### Extended collections

An extended collection has `extends`, `modeMap`, and optional `overrides`. The parent is a typed collection address. `modeMap` maps every child mode to one immediate-parent mode. Parent chains are acyclic.

An extension inherits root variable identities; it does not clone or own new variables. Overrides use this syntax:

```json
"overrides": [
  {
    "variable": { "resource": "surface-color" },
    "values": {
      "brand-day": { "ref": { "resource": "brand-white" } }
    }
  }
]
```

Overrides may address only inherited root variables and declared child modes. There may be at most one override record per variable. Missing override means inherit, not null. The expression is authored in the extending package's dependency namespace.

Selecting an extension chooses one view of the root variable set. Resolution checks the selected child for an override, then follows its mapped parent mode and checks the immediate parent, continuing to the root value. Only one leaf view can apply to a root in one selection list. An extension's default does not activate that extension when no view was selected; the root default remains active.

## 8. Concrete values and native mappings

[The generated field reference](../docs/fields.md) and `values.schema.json` define all field shapes. These rules fix deliberate differences from raw Figma API payloads:

1. **Colors:** `{ space, channels, alpha }` replaces raw RGB/RGBA records. Spaces are `srgb`, `display-p3`, `hsl`, `hsb`, `oklab`, and `oklch`. RGB coordinates and alpha use [0,1]. HSL/HSB use degrees [0,360) followed by two [0,1] coordinates. OKLab uses normalized lightness followed by signed a/b; OKLCH uses normalized lightness, nonnegative chroma, and hue degrees. No conversion or gamut clipping is implicit. A source adapter must convert source coordinate units explicitly and retain the authored color space; fallback RGB is not a replacement for an authored source color.
2. **Native numeric fields:** payload names and enum spelling follow Figma. Numeric sizes, offsets, spacing, radii, and dimensions are in native pixel units unless the owning record declares units. Native `timing` is a nonnegative scalar in seconds; `duration` is a quantity `{ amount, unit: "ms" | "s" }`. Native numbers do not silently become quantity records. A quantity's numeric component can be selected explicitly with a pointer.
3. **Geometry:** a transform is `[[m00,m01,m02],[m10,m11,m12]]`, mapping x to m00*x+m01*y+m02 and y to m10*x+m11*y+m12. Gradient geometry accepts exactly one of Plugin API `gradientTransform` or REST `gradientHandlePositions`; the latter contains three normalized points. Geometry is not reduced to an angle. Standalone `point` and `transform` values declare `space: "pixels" | "normalized"`.
4. **Stack identity:** paint/effect/grid entries and gradient stops require immutable local `itemId`. Item IDs are unique within their array. Ordered arrays preserve Figma authoring stack order, with index 0 topmost. They are never sorted by name. API reconstruction must account for the native renderer's evaluation rules separately.
5. **Assets:** image/video native hashes, pattern source-node IDs, shader IDs, and animation provider style IDs become typed `asset` addresses. Native IDs may additionally be retained as source mappings. Fonts may attach a font asset to `fontName`. A vector region's native fill-style ID becomes a typed `fillStyle` address to a paint style.
6. **Bindings:** raw `VariableAlias` and `boundVariables` records are not accepted as concrete payloads. Explicit FFS `ref`/`bind` expressions represent these relationships. This avoids two competing authoritative binding representations.
7. **Automatic values:** grid count uses `"auto"`, not Infinity. Line height preserves `unit: "AUTO"`, measured `PIXELS`/`PERCENT`, or the REST distinction `INTRINSIC_PERCENT`. Zero and null never mean automatic.
8. **REST differences:** image paints can preserve `scaleMode: "STRETCH"` and an additional animated `gifAsset`; patterns may preserve `verticalAlignment`. `EMOJI` paints require a rendering asset and may include the original `emoji` string. This is an explicit FFS representation for a REST-listed paint kind; the format does not invent an undocumented Plugin API emoji object. `fontPostScriptName` is available in text-property presets.
9. **Text styles:** native Text Style fields are required for a complete style definition. Text presets are partial property sets; an omitted field is unspecified. OpenType feature flags are sparse known-tag dictionaries. Font-variation axis tags are four printable ASCII characters. Font availability and actual font-axis ranges are integration concerns requiring the real font, not assumptions based on a family name.
10. **Motion:** reusable custom animation styles retain their entries, provider assets, configuration, duration/offsets, and typed property assignments. Figma easing includes named curves, custom Bezier and normalized spring data, and HOLD. Physical springs are a separate type; they are not silently treated as normalized springs. Per-node tracks and timelines stay in the future component/document format.

Optional payload fields remain omitted when not authored. The resolver does not inject native defaults. A preset omission means “do not assign”; optional native-style/paint fields use the corresponding native baseline's default when applied by an integration. Exact captured source settings should be serialized explicitly when reproducibility depends on them.

## 9. Native binding eligibility

The core evaluator permits bindings only at the positions below, with compatible native variable types. Paths are relative to the owning resolved value. Ordered stacks prepend their array index.

| Destination | Permitted fields |
| --- | --- |
| Solid paint / gradient stop | `color` — color variable |
| Drop/inner shadow | `color`, `radius`, `spread`, `offset.x`, `offset.y` |
| Layer/background blur | `radius` |
| Layout guide | `sectionSize`, `count`, `offset`, `gutterSize`, where that variant exposes the field |
| Text style or preset | `fontSize`, `fontWeight` where present, `paragraphSpacing`, `paragraphIndent`, `letterSpacing.value`, `lineHeight.value`, `fontName.family`, `fontName.style` |
| Layout preset | Padding, item/counter-axis spacing, grid gaps, min/max dimensions |
| Corners / stroke preset | Individual corner radii and stroke weights |
| Motion properties | Declared animation `props` entries |
| Shader | Typed dynamic property assignments and metadata defaults |

Unknown/beta native fields are not assumed bindable. Adding bindable positions requires a specified mapping. The resolved contract still validates the resulting value, so a color cannot bind to a numeric radius merely because both are variable references. Scopes remain authoring metadata, not a substitute for type checks.

## 10. Assets and integrity

An asset declares a MIME `mediaType` and one content variant:

- `file`: package-relative `path`, `sha256`, and `byteLength`.
- `embedded`: canonical padded `base64`, `sha256`, and `byteLength` of decoded bytes.
- `external`: `provider`, provider `id`, and optional provider `version`.

Bundled content MUST match both its digest and byte length. External content is never fetched implicitly and MUST NOT be described as bundled. An external shader ID preserves a dependency; it is not transferable shader source code. External font, video, and animation availability cannot be proven by JSON validation.

Paint/font/motion asset fields require compatible media types. `gifAsset` specifically requires `image/gif`. Shader content uses `application/vnd.figma.shader`; reusable provider animations use `application/vnd.figma.animation-style`. Pattern artwork uses SVG or `application/vnd.ffs.vector+json`. Embedded/file vector JSON is validated against `vectorArtwork` and its resource relationships; full component scenes are not legal pattern payloads.

Resource reference graphs, including bounded artwork dependencies, MUST be acyclic. Bundled binary integrity does not prove visual equivalence, license availability, or successful reconstruction by an integration.

## 11. Resolution and conformance

A conforming core evaluator MUST:

1. Load/assemble packages and verify dependency identities and exact byte digests.
2. Validate the authored envelope, resource shapes, expression grammar, IDs, collections, modes, ordering lists, and source links.
3. Validate every authored relationship, including inactive branches and extension overrides.
4. Reject reference/inheritance/dependency cycles. Version 0.1 conservatively rejects resource cycles even if one selected context would avoid the cyclic branches.
5. Evaluate the entire finite product of root/extension view choices and mode choices, then validate concrete values and binding eligibility. This catches invalid interactions across independent collections.
6. Fail explicitly if it cannot finish validation within its declared resource budget. A budget failure is not a valid package and is not a format-imposed mode-count limit.
7. Resolve a requested context without modifying the authored document or replacing its reference graph with flattened data.

The reference validator defaults to 4096 contexts and supports a higher `maxContexts` setting. This option MUST be a positive safe integer; NaN, Infinity, fractions, and zero are invalid arguments. It never labels an incompletely checked package valid. It currently reports the first error, including a stable code and a source/resource pointer when available.

The resolver returns `format: "figma-foundations-resolved"`, format/package identities, the explicit context, and value-bearing root resources. Each output resource includes `dataType`, concrete `value`, native `bindings`, and resolved resource `references`. References preserve origin identities across imported values, including dependency-local asset/style addresses. This output is an evaluation artifact, not an authored-package replacement or a Figma document.

## 12. Authoring manifests

A manifest has the same metadata as a package, but `format` is `figma-foundations-manifest` and `resources` is an ordered, nonempty array of unique package-relative JSON file paths. Each fragment contains a resource-ID dictionary. Assembly rejects duplicate IDs across fragments and duplicate JSON keys within them. Resource semantics do not depend on file order.

The assembled output changes `format` to `figma-foundations` and combines the resource dictionary. Organization retains its explicitly authored order. The reference loader records fragment source files for diagnostics. Assembly validates the result; it is not an unchecked concatenation.

Moving an assembled file to another directory requires moving or correctly repackaging its relative dependencies/assets. The CLI refuses to overwrite an existing `--output` destination.

## 13. Evolution and implementation limits

Changing a field's meaning, accepted representation, required fields, or evaluation behavior requires an explicit format release. Package content can evolve separately. Renaming or regrouping keeps IDs; replacing a logical entity creates a new ID and may deprecate the old one with a replacement address.

Pre-1.0 releases may introduce breaking changes, but each versioned schema is retained and changes are documented. This implementation accepts exactly 0.1.0 and rejects other format versions. The repository's examples use the implemented syntax.

The reference implementation validates and resolves this contract locally. It does not implement a Figma import/export plugin, render effects, reconstruct shaders, verify provider permissions, fetch remote assets, or prove live Figma round-trip fidelity. Those are separate integration tasks. Its coverage claim is the documented foundation baseline above, not every feature of every Figma product or future Figma release.
